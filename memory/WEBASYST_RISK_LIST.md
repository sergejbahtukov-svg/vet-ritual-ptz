# Риски Webasyst → WordPress (для закрытия перед BUILD)

## 1) Route и контентный drift
1. Риск: дублирующиеся и альтернативные URL (`/about/`, `/vyvoz-umershih-zhivotnyh/`, `/vyvoz-umershikh-zhivotnyh/`, `/vyvoz-tela-zhivotnogo/`) дадут дубли в индексе.
2. Риск: потеря fallback-контента при отсутствии данных ACF/Options для страниц.
3. Риск: неконсистентные алиасы между меню и содержимым.
4. Митигация:
   - Поддержать canonical/redirect на WP.
   - Настроить единый роут-контроль и план URL в `PAGE_FIELD_PLAN.md`.
   - Ввести контракт `THEME_SETTINGS_CONTRACT.md` для обязательных fallback-значений.

## 2) SEO и каноническая целостность
1. Риск: потеря ручных SEO-тегов на внутренних страницах при некорректном парсинге page-title/page-description из старого `index.html`.
2. Риск: 404 страницы начнут индексироваться как основные.
3. Митигация:
   - Ввести `SEO_MIGRATION_MATRIX.md` с 1:1 маппингом SEO.
   - Обязательно `noindex` для 404 и корректный robots на всех новых шаблонах.

## 3) Безопасность контента
1. Риск: прямой вывод `$page.content` в Webasyst аналогичен выводу из редактора; в WP нужен контроль экранирования.
2. Риск: неконтролируемые вставки через `vr_custom_head_html`/`vr_body_*_html`.
3. Митигация:
   - Только роль администратора для полей произвольного HTML.
   - `wp_kses_post` для контентных блоков и явный allow-list для интеграционных вставок.

## 4) Интеграции и cookie-согласие
1. Риск: analytics начнет грузиться до согласия и нарушит UX/политики.
2. Риск: разные способы отображения consent в браузерах/без JS сломают функционал.
3. Митигация:
   - Поддержать `always | after_cookie_accept | disabled` с default = `disabled` как в текущей теме.
   - Тест smoke по `localStorage` ключу + ручное включение/отказ в dev.

## 5) Технический риск WordPress-реализации
1. Риск: потеря корректности `assets`-версионирования и кеша из-за постоянной смены версий.
2. Риск: неполная структура темы (отсутствует `theme.json`, `inc/`, helper).
3. Митигация:
   - Для разработки зафиксировать `theme.xml` и `?v=` на `1.0` до релиза.
   - Обязательные файлы: `style.css`, `functions.php`, `inc/helpers/theme-options.php`, `template-parts/`, `theme.json`.
