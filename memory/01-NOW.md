# 01-NOW — текущий план запуска

## Главная задача
- Подготовить и зафиксировать готовый workflow для миграции Webasyst → WordPress с разбивкой на сабагентов.

## На чем остановились
- Подготовлены и очищены входные документы для нового этапа.
- Следующий шаг: запуск подзадач по роли сабагентов и наполнение их артефактами.
- Обновлена архитектура памяти до LLM-ориентированного вида: добавлены доменные карты и протокол самоочистки.

## Режим выполнения на ближайший слот
1. Проверить и запустить доменные карты:
   - `memory/OFFER.md`
   - `memory/AUDIENCES.md`
   - `memory/FUNNEL.md`
   - `memory/SITE.md`
   - `memory/ADS.md`
   - `memory/ANALYTICS.md`
2. Аудит Webasyst: финализировать карту страниц, блоков и роутов в `memory/WORDPRESS_MIGRATION_WORKFLOW.md`.
3. Архитектура WP: утвердить структуру темы, CPT/ACF/меню/редиректы.
4. Карта контента: связать все URL и смысловой контент с шаблонами.
5. SEO + QA: зафиксировать требования к мета-тегам, OG, schema, redirects и smoke-check.
6. Запусковый маршрут: staging → pilot → production с планом rollback.
7. Запустить `memory/scripts/memory-gc.ps1` и обработать отчёт (`memory-cleanup-report-*`), без удаления до ручного решения.

## Риски и ограничения
- На этапе перехода нельзя опираться на `preview.html` как источник истины.
- Не открывать тему архивами вне `deploy-vetritual-modern/`.
- Любые изменения в интеграциях делать как кодовую миграцию:
  - загрузка аналитики по согласиям,
  - cookie banner,
  - SEO-блоки в head.

## Контроль результата
- На каждой фазе обязательная запись в:
  - `memory/WORKLOG.md`
  - `memory/DECISIONS.md`
  - `memory/EVIDENCE.md`

## Текущее состояние памяти
- Карта доменов заполнена, но в полях `ADS.md` и `ANALYTICS.md` отмечены точки уточнения (`не определено`) для точного закрепления после проверки интеграций.
